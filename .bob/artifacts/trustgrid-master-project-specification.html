Project Summary

TrustGrid is a dynamic, ML-assisted trust scoring and privilege engine for two-sided e-commerce marketplaces. It is not primarily an e-commerce website. The demo marketplace exists solely to generate behavioral events that feed the trust engine.

Core product: A trust-as-a-service engine that evaluates buyer and seller marketplace behavior, produces a dynamic Trust Score (0–1000), a Confidence level (LOW / MEDIUM / HIGH), and grants or revokes marketplace privileges accordingly.

Key Differentiators vs. Simple Star Ratings

  • Behavioral signals replace static accumulated ratings
  • XGBoost estimates per-dimension reliability, not just a count
  • Exponential time decay (90-day half-life) — recent behavior outweighs old
  • Confidence layer prevents new accounts from gaming maximum privileges
  • Explainable score changes shown in plain language to users
  • Centralized privilege engine driven by score + confidence + tier

Trust Scoring Methodology

Buyer — Five Dimensions

Order Reliability

25%
  • Completed orders
  • Successfully received orders
  • Not frequency of purchase

Return Behaviour

25%
  • Return rate (decayed)
  • Return frequency
  • Normal returns not punished

Payment Reliability

20%
  • Successful simulated payments
  • Failed payment rate
  • Abandoned checkout rate

Cancellation Behaviour

15%
  • Buyer cancellation rate
  • Repeat cancellation penalty

Platform Engagement

15%
  • Successful referrals
  • Reviews submitted
  • Infrequent buying ≠ penalty

Seller — Five Dimensions

Order Fulfillment

25%
  • Fulfilled orders rate
  • Seller-side cancellations

Delivery Performance

25%
  • On-time delivery rate
  • Late delivery rate

Customer Satisfaction

20%
  • Average product rating
  • Customer complaints

Return & Dispute Handling

15%
  • Return response rate
  • Resolution success rate
  • Failure to respond penalty

Platform Reliability

15%
  • Product listing consistency
  • Policy compliance

Time Decay

Exponential decay with a 90-day half-life. λ = ln(2)/90 ≈ 0.00770.
weight(age_days) = exp(−λ × age_days) λ = ln(2) / 90 ≈ 0.00770 Examples: age = 0 days → weight ≈ 1.000 age = 30 days → weight ≈ 0.794 age = 90 days → weight ≈ 0.500 age = 180 days → weight ≈ 0.250 age = 270 days → weight ≈ 0.125

Score Calculation

-- Each dimension Dᵢ is on 0–100 from ML reliability output × 100 RawScore (Buyer) = 0.25×D1 + 0.25×D2 + 0.20×D3 + 0.15×D4 + 0.15×D5 TrustScore = clamp(round(10 × RawScore), 0, 1000)

Score Smoothing

NewScore = α × ModelScore + (1−α) × PreviousScore α scales with evidence volume: 0–5 events → α = 0.20 (score barely moves) 6–15 events → α = 0.40 16–30 events → α = 0.65 31+ events → α = 0.85 (model dominates)

ML Plan

Why XGBoost

Tabular behavioral data, non-linear feature interactions, mixed numerical inputs, relatively small dataset size, and the need for fast inference at event-time all favor gradient-boosted trees over deep learning. XGBoost is well-understood, produces feature importances natively, and integrates cleanly with scikit-learn pipelines.

Synthetic Dataset

Target: ~20,000–50,000 event records. User profiles generated with realistic behavioral distributions:

Buyer ProfileSeller Profile
Reliable BuyerExcellent Seller
Occasional but Reliable BuyerReliable Seller
Frequent ReturnerSlow Seller
Frequent CancellerHigh Cancellation Seller
Poor Payment BehaviourPoor Return Handling Seller
Mixed BehaviourMixed Seller

Feature Vector (per user, time-decayed)

Buyer:   order_completion_rate, return_rate, payment_success_rate,
         cancellation_rate, referral_count, review_count,
         recent_order_completion_rate (last 30d), account_age_days,
         decayed_order_weight, decayed_cancellation_weight

Seller:  fulfillment_rate, late_delivery_rate, avg_rating_received,
         return_response_rate, return_resolution_rate,
         seller_cancellation_rate, product_count,
         recent_fulfillment_rate (last 30d), account_age_days

Target Variable

Binary: is_reliable — did the user complete transactions successfully in the next window (future 30 days) based on historical patterns. Constructed from synthetic behavioral labels to avoid data leakage. Features use only events before the target window.

Train / Validation / Test Split (Chronological)

Training set → transactions from months 1–8 (~70%) Validation set → transactions from months 9–10 (~15%) Test set → transactions from months 11–12 (~15%)

Evaluation Metrics

  • Precision, Recall, F1 (primary for imbalanced dataset)
  • ROC-AUC
  • Confusion matrix
  • Feature importance plot (XGBoost native)
  • Optional: SHAP summary plot

Model Deployment

Offline training only. Model is trained once on the synthetic dataset and persisted via joblib. FastAPI loads the saved model at startup. Retraining is a future enhancement — no retraining per user event in the prototype.

Backend Integration Flow

Event arrives → EventService.record(event)
             → FeatureEngine.update_features(user_id)   # time-decay applied
             → model.predict_proba(feature_vector)      # XGBoost
             → dim_scores = transform_proba_to_0_100()
             → TrustEngine.calculate(dim_scores, prev_score, event_count)
             → ConfidenceService.evaluate(event_count)
             → PrivilegeEngine.recalculate(score, confidence, tier)
             → ScoreHistory.append(change, reason)
             → ExplanationService.generate_reasons(delta_features)
             → Return updated TrustGrid state
