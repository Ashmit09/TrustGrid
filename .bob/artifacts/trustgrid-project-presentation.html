The Problem

Why existing marketplace reputation systems fall short

⭐
Static Star Ratings
A 5-star review from 3 years ago carries the same weight as one from yesterday. History is treated as timeless.
🔢
No Evidence Quality
A score from 2 transactions is displayed identically to one from 2,000. Confidence in the score is invisible.
🤷
No Explainability
Users see a number change but never understand why — what behaviour caused it, or how to improve it.
2

The Solution

TrustGrid's core idea

💡
TrustGrid models trust as a dynamic, evidence-gated score derived from observed marketplace behaviour. It combines multi-dimensional rule-based scoring with an XGBoost ML model, weighted by exponential time decay, and gated by a confidence level that reflects how much evidence exists — ensuring no brand-new account can unlock high-value privileges on day one.

Scoring Mechanics

Three layers that make the score accurate, stable, and fair

⏳
Exponential Time Decay
Recent events carry more weight than old ones. Events from 90 days ago contribute half the weight of today's events. Behaviour from last year has minimal influence.
w(t) = exp(−λ × age_days)
λ = ln(2) / 90 ≈ 0.00770

w(0d) ≈ 1.000
w(90d) ≈ 0.500 ← half-life
w(270d) ≈ 0.125
🤖
ML Blending
XGBoost provides P(reliable). The model's influence grows with evidence — new users are pure rule-based; experienced users blend ML output with rule scores.
β = 0.0 (weight < 1) — new user
β = 0.3 (weight 1–10) — early
β = 0.5 (weight > 10) — established

final = β × ml_raw + (1−β) × rule
📊
Score Smoothing
A single event cannot cause a large score swing. Alpha blending with the previous score prevents volatility. Low confidence = high inertia.
new = α × model + (1−α) × old

α = 0.20 (LOW confidence)
α = 0.50 (MEDIUM confidence)
α = 0.80 (HIGH confidence)

Key System Features

What makes TrustGrid distinctive

🛡️
Evidence-Gated Privileges
Benefits require both a minimum score AND a minimum confidence level. New accounts cannot unlock high-value privileges on registration day.
💬
Plain-English Explanations
Every score state has a human-readable explanation: driving factors, strongest/weakest dimensions, and personalised improvement recommendations.
🔮
What-If Score Simulator
Users can project their score before acting — "What if I complete 10 more orders?" — without any real database mutation.
⚖️
Infrequent Buyer Protection
Purchase frequency is not a feature. A buyer who orders once a year with perfect reliability scores identically to a daily buyer with the same rates.
📜
Immutable Event Log
Every trust event is append-only with a timestamp. Complete audit trail enables retrospective recalculation and full explainability.
📉
Generous Return Policy
A return rate ≤10% receives a perfect dimension score. Only buyers with systematically high return rates (>30%) are meaningfully penalised.
